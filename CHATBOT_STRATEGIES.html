AI/chatbot challenge scripts

Choose a strategy after inspecting the challenge page and its JavaScript. The scripts provide bounded transport, session handling, and evidence collection; they do not infer an unknown endpoint, tool grammar, model wrapper, or win condition. All live commands require an authorized origin and finite budgets.

Live chat playbooks

List the built-in plans and their required parameters:

python3 scripts/autosolve.py --json chatbot-strategies

Copy a protocol example, set the actual chat path, fields, cookies or headers from the frontend, and run a dry run first:

python3 scripts/autosolve.py chatbot --origin https://AUTHORIZED_ORIGIN \
  --protocol ./private-chat.json --strategy context_bloat \
  --budget 60 --max-requests 12 --max-prompts 6 --dry-run
python3 scripts/autosolve.py chatbot --origin https://AUTHORIZED_ORIGIN \
  --protocol ./private-chat.json --strategy context_bloat \
  --budget 60 --max-requests 12 --max-prompts 6

context_bloat sends an anchor and then 512, 2,048 and 8,192 characters of neutral filler by default in one conversation. It records the first size at which the target stops returning the original marker. Set strategy_params.sizes to one to four increasing sizes, each 128–65,536 characters; filler, anchor_prompt, and check_prompt are optional. A lost marker is a behavior observation, never a validated challenge solve. The generated marker and queue survive resume. The client will not resend a POST whose outcome is uncertain.

The selected strategy sends its listed probes after one baseline. It does not run every strategy or the whole CHY corpus. A response that reveals a route or secret stops broad prompting. The private run contains a JSONL transcript, candidate and checker evidence, cookies, and a report. The ordinary terminal output contains only status and file paths. --max-requests is at most 100, --max-prompts at most 20, and --budget at most 600 seconds. The HTTP client also caps each response at 128 KiB, each request body at 128 KiB, and its transcript at 2 MiB.

For a tool-header capture, start the bounded callback receiver first. Its default bind is loopback, and it exits after one request or its duration. A remote challenge can reach it only if you deliberately provide a reachable authorized address; put that address in the protocol's authorized_destinations before selecting fetch_tool. Raw callback headers stay in a private JSONL file.

python3 scripts/chatbot_callback.py --port 0 --max-requests 1 --duration 60

When a guardrail returns code points, character arrays, NATO words, initials, reversed text, groups, or Base64, save the exact response in a private text file and decode it as a candidate. The tool-call audit helper compares args_raw, args_validated, args_normalized, and args_applied from a JSON response or a chosen transcript line. It reports changed paths and hashes, never proof of applied backend state.

python3 scripts/chatbot_evidence.py decode --input ./private-reply.txt --mode codepoints
python3 scripts/chatbot_evidence.py audit --input .autosolve/runs/RUN_ID/transcript.jsonl \
  --line 5 --raw-field tool_calls.0.args_raw \
  --validated-field tool_calls.0.args_validated \
  --normalized-field tool_calls.0.args_normalized \
  --applied-field tool_calls.0.args_applied

Direct application routes

Select api_plan when the decisive path is a normal API. It uses the same origin, cookie jar, redirects, request budget, and private transcript. A plan contains one to ten declared GET or POST steps; POST requires allow_state_change: true. A configured expect compares an exact response field. Only an official checker/completion step marked acceptance: true can mark a result validated. An expected field match on a history or vector-store response is evidence, not a solve.

Start from the history, vector-store, debug/verifier, scorer-batch, tool-audit, or workflow examples. Replace every REPLACE_ field before live use; the CLI rejects live plans that retain one. The KB example shows an explicit writable injection surface. Do not enumerate IDs, origins, or ports by changing a plan into a bulk scanner. For SQLi, SSRF, IDOR, auth bypass, or other ordinary web bugs, use the web workflow once the relevant primitive is observed.

python3 scripts/autosolve.py chatbot --origin https://AUTHORIZED_ORIGIN \
  --protocol ./private-api-plan.json --strategy api_plan \
  --budget 60 --max-requests 12 --max-prompts 1 --dry-run

Offline model and scorer routes

The offline helper does not deserialize pickle files or run a supplied wrapper during inspection. It reports bounded metadata from NPY, NPZ, safetensors, zip-backed PyTorch files, and pickle globals. A small pair of NPZ or safetensors files can be compared when NumPy (and, for safetensors, that package) is installed. Parity runs two explicit wrapper commands on up to 20 JSON canaries and requires --execute-local.

python3 scripts/ai_model.py inspect ./model.safetensors
python3 scripts/ai_model.py compare ./base.npz ./challenge.npz
python3 scripts/ai_model.py svm ./private-svm-parameters.json
python3 scripts/ai_model.py sign-gates ./private-sign-gates.json --timeout 10
python3 scripts/ai_model.py parity ./private-parity.json --execute-local
python3 scripts/ai_model_attack.py --adapter ./private-adapter.py --execute-local \
  gradient --model ./model.pt --input ./input.npy --target chosen-class \
  --epsilon 0.1 --step-size 0.02 --steps 10
python3 scripts/ai_model_attack.py --adapter ./private-adapter.py --execute-local \
  recurrent --actions ./actions.json --seed 0

A parity config supplies reference and candidate argv arrays, cases, a per-call timeout (at most 30 seconds), and a total budget (at most 600 seconds). Each wrapper reads one JSON value on stdin and prints one JSON value on stdout. The script uses no shell and records only case indexes, equality, and output hashes in a private report. It never claims that matching canaries prove full inference parity.

Copy the model adapter template for gradient or recurrent runs. Gradient mode needs load_model(path), load_input(path) returning a floating PyTorch tensor, and loss(model, tensor, target) returning one scalar to maximize. It applies bounded projected gradient steps and saves an NPY candidate; it does not serialize a challenge submission. Recurrent mode needs reset(seed), policy_step(observation, previous_action, hidden), and env_step(action). It records pre/post auxiliary vectors with one policy call per observed state, avoiding a duplicate hidden-state advance. Both modes execute the adapter only with --execute-local. That opt-in is not a sandbox. NumPy and PyTorch are optional local requirements for gradient mode.

For a deterministic sign network, export the actual affine gates and input bounds into the sign-gate JSON example. ai_model.py sign-gates uses Z3 when installed, returns one satisfying input, and checks whether another input also satisfies the declared constraints. It does not infer gates from a model or treat a satisfying assignment as a validated flag. The supplied checker must accept the serialized candidate.

These scripts cover repeatable mechanics, not arbitrary model semantics. A specialized solver still needs the challenge's wrapper, data constraints and acceptance endpoint. Refusals, marker echoes, high model scores, and plausible identifiers remain candidates until independent state or checker evidence confirms the objective.
