# Round 2: core-tool usefulness and portability

The workbook distinguishes **32 tools proposed by Trend Micro** (`windows-1`–`windows-32`) from **168 participant requests**. The colour is an origin label, not an official priority ranking or a written guarantee that those 32 solve every challenge. This distinction now controls the guide's ordering and visible labels. [Workbook cell and row evidence](authority/REPORT.md) maps all 200 approval IDs.

## What became more useful

- [Core workflows](../../CORE_WORKFLOWS.md) turn CyberChef, packet analysis, image/PDF, disk, native, web, memory, RSA and CAN starting points into actions with expected evidence and failure checks. The [authored practice pack](../../examples/core/README.md) includes exact positive and negative inputs. [All 200 entries](../../CTF_CHEATSHEET.md) remain in their own Markdown sections.
- Actual [CyberChef, TShark and Ghidra exercises](tool-exercises/README.md) verified a layered decode, 51-byte TCP object reconstruction and a recovered C comparison. A separate [workflow exercise](workflow-gaps/README.md) checked 29 commands across zsteg, qpdf, a deleted ext2 file, GDB and an explicit RSA case. Nine more proposed [utilities](core-utilities/README.md) were exercised on authored data. These are scoped local observations, not competition-machine guarantees.
- [Volatility 3](memory/REPORT.md) processed an official 32-bit XP test image with an owned matching symbol cache and networking disabled. `windows.info`, `pstree`, `cmdline` and one known-address extraction passed; 47 process rows and two extracted PE hashes matched publisher test expectations. The guide now includes the explicit symbol and cache paths that its working commands used. This does not test the missing practice challenge's dump or modern Windows.
- Template [adaptations](template-exercises/REPORT.md) passed a fresh 100-question menu protocol, binary frames and a cookie/nonce HTTP flow. Tested replacement blocks were added to the template guide. Python 3.11 and 3.12 [runtime checks](runtime/REPORT.md) established standard-library behavior, unusual paths and actionable missing-pwntools errors. Native Windows/Kali and Python 3.10 remain untested.

## Repairs that required a second check

- zsteg help succeeded while its real scan failed because the local container lacked `file`. A narrowly rebuilt project image added that dependency; default scan, selected-plane extraction, wrong-plane and empty-carrier controls passed. The tool still strips trailing NULs. [Repair evidence](zsteg-repair/README.md).
- Stock `asc2log` sometimes moved identical timestamps back one hour and mishandled AM; a missing locale initially caused current-time substitutions. An independent [cause review](can-repair-review/REPORT.md) reproduced the DST field and tested a two-line source patch. The [local patched image](can-date-integration/README.md) then passed exact date and frame checks, retaining its original binary and rollback image. Malformed rows can still be dropped at exit 0, and invalid dates still require comparison with the original. No hardware, CAN tunnel or competition version was tested.
- The project container runner silently changed an outside working directory to the project root, which could read a different same-named file. It now exits before Docker with an explicit error. [Distinct independent retest](runtime/launcher-boundary-after.json) confirmed outside rejection and inside-project access.
- A later [independent content review](../review-recipes/REVIEW.md) caught the per-tool Volatility recipe invoking `vol.py` from an assumed checkout and a missing symbol path in the core example. Both now use the installed `vol` launcher with explicit `--offline`, `-s` and `--cache-path`. The final command ran on the owned XP fixture in a network namespace. These findings were fixed before final export.
