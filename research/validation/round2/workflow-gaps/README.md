## Fresh exercise and observations

`exercise.py` generated all inputs in this directory. It uses the installed Python 3.12 environment with Pillow and Scapy, existing CLI tools, repository qpdf/zsteg/RsaCtfTool launchers and the already present Docker image. No installation, host scan, live capture, organiser/PX launch, downloaded executable, or real memory image was used. It compiles and executes only the transparent C source it writes. The filesystem is a regular disposable file; nothing is mounted.

```bash
/opt/ctf-tools/py312/bin/python research/validation/round2/workflow-gaps/exercise.py research/validation/round2/workflow-gaps/NEW_RUN
```

The current harness deliberately expects the known default zsteg missing-`file` failure, verifies its cause, then tests the documented reduced fallback. If that environment defect is repaired, update this expected-failure control before rerunning; do not describe the failed default as working. Use a new output directory. It creates about 18 MiB of synthetic filesystem images plus small fixtures and per-command stdout/stderr logs. It is research evidence, not a proposal to distribute a new abstraction.

`run-3/summary.json` records 29 command invocations with their expected exits and independent byte/content assertions. A failure control returning its expected nonzero exit is not a successful normal-tool operation.

`run-3/rsa-independent-check.json` additionally parses the key RsaCtfTool actually recovered, compares both factors to the authored factors, decrypts with that key and re-encrypts. This installed tool emits its result on stderr: stdout is zero bytes. Do not teach `RsaCtfTool ... > private.pem` as a raw-key export. Its output can combine logs, labels, ANSI escapes and multiple representations; use a documented output option only after checking what it contains, or copy just the PEM block to a new file and parse it.
