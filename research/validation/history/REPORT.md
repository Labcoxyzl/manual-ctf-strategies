# Historical Cyber SEA Game validation

Four public artifact cases exercised packet reconstruction, NTLMv2 parsing, five-bit encoding and static unpacking. One additional historical web case exposed a real usability gap in `http_probe.py`: it hid response headers. The coordinator repaired that gap, and an independent rerun of the same local fixture passed. No historical service was contacted and no downloaded executable or solver was run.

The evidence is in [historical-evidence.json](historical-evidence.json); [downloads.json](downloads.json) records all 25 file URLs, immutable repository commits, sizes, SHA-256 hashes and Git blob checks. Public files and raw decoded material are under `artifacts/` and must be excluded from reusable exports. These are participant-hosted copies; matching Git blobs establishes retrieval integrity, not organizer authenticity.

The 2019 event is confirmed by the [Japan–ASEAN Integration Fund record](https://jaif.asean.org/en/news/cyber-sea-game-2019), which identifies ETDA/AJCCBC and the 20–22 November event programme. The organizer confirms [Cyber SEA Game 2025](https://ajccbc.ncsa.or.th/cyber-sea-game-2025) ran in Bangkok on 16–17 October. Challenge-level attribution comes from the linked participant repositories. These are Cyber SEA Game sources, not an unrelated SEA-named CTF.

For Intact, [results/intact-verification.json](results/intact-verification.json) records payload hashes and extraction checks. For N4, [results/betrayer-verification.json](results/betrayer-verification.json) records field lengths and independent agreement. A raw signature scan sees a repeated Type 2 message, so counting signatures is insufficient. The capture confirms an NTLMv2 exchange; the participant’s wider poisoning/relay attribution was not independently established, and no password was cracked. [Participant writeup](https://github.com/kaisonox/CTFs/blob/3ad3035d46d9453811d064866461f23b46349b0a/2025-Cyber-SEA-Game/Switzerland_N4_betrayer/README.md).

C6 is deliberately a partial-decoding result. The public solver truncates leftover bits and forces letter mode; those shortcuts should not enter the generic helper. The independent baseline handled 18 shift controls and retained the three-symbol limitation. ITA2 is a five-unit code with stateful letter/figure shifts, as defined by [ITU-T S.1 §§1.2, 3 and 4.4](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-S.1-199303-I%21%21PDF-E&lang=e&type=items). See [results/c6-verification.json](results/c6-verification.json).

The packer result is explicitly informed by the [participant’s published key and RVA](https://github.com/kaisonox/CTFs/blob/3ad3035d46d9453811d064866461f23b46349b0a/2025-Cyber-SEA-Game/Greece/README.md); those constants were not independently recovered from the loader. The resulting PE structure and answer-pattern hash were verified. See [results/packer-verification.json](results/packer-verification.json). This tests a useful workflow boundary without claiming dynamic malware-analysis coverage.

The web repair has a direct historical reason: the Singapore participant’s [2021 Known Vulnerability 1 writeup](https://nandynarwhals.org/cyberseagame-2021/) begins with the response’s Apache version header. The harmless local fixture returned `Server: Apache/2.4.49`, `X-Training-Marker: header-visible`, and a short body. Before the repair, curl displayed both headers while `http_probe.py` printed only status/body. After the repair, both headers and the body appeared with exit 0. [Before observation](results/http-header-observation.json) · [After independent rerun](results/http-header-after-observation.json). This was a simulated response, not an Apache vulnerability test; a version string alone does not establish exploitability.

There is also credible native-exploitation coverage to add to the guide, without a solved claim. The [2022 coal_mine artifact](https://github.com/sudlit/ctf-writeups/blob/275a8e965ad4bc4536d52bd711b8f7503d914383/Cyber%20SEA%20Game%202022/coal_mine/coal_mine) is an ELF64 PIE. Static disassembly confirms a user-controlled `printf` format, a later `gets`, a separate marker check and a stack canary. The [participant solver](https://github.com/sudlit/ctf-writeups/blob/275a8e965ad4bc4536d52bd711b8f7503d914383/Cyber%20SEA%20Game%202022/coal_mine/solve.py) uses positional leaks and libc ROP; its offsets and chain were not exercised. Map this to Miscellaneous/native exploitation and refer to the existing pwntools scaffold only for transport. The local binary requests a relative loader, so execution would require its matching environment rather than guessing at host libc.

Additional leads remain weaker: 2019 Unlock includes a capture and TLS-key archive, but decryption was not repeated. The 2025 N2 capture was confirmed to contain five SIP and 748 RTP packets, but audio/Morse recovery was not repeated. The 2019 web writeups lack full server source; a small uploaded firmware example does not make a replayable web challenge.

The coordinator also changed `ctf.py` during this work. All three historical `inspect` paths and the C6 strict-width rejection were rerun against SHA-256 `cdbe6280225117426630ec9d61700402d3a16fe57134774a7f2dc748bd57ca2d`; their facts and scope remained unchanged. [Current-helper revalidation](results/helper-after-verification.json).

Validation used CPython 3.12.3, TShark 4.2.2, file 5.45, Scapy 2.7.0, pefile 2024.8.26 and PyCryptodome 3.23.0. These are local versions, not confirmation of competition-machine readiness. Approved inventory routes used are Wireshark (`windows-2`), TShark (`windows-36`), Python (`windows-7`), CyberChef (`windows-1`), 7-Zip (`kali-2`), hashcat (`kali-59`), objdump (`windows-10`), strings (`windows-11`) and radare2 (`kali-116`).

Skipped: no live submissions, historical host probes, executable loading, password cracking or generic new decoder. Remaining risks: participant copies lack organizer checksums; C6 retains three unexplained symbols; source-informed unpacking does not prove autonomous reverse engineering.
