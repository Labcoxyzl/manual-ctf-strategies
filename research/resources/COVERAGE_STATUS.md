# Coverage status — 27 October 2026

The current [route data](../../research/routes.json) has 44 task routes across all seven event categories. They use 76 distinct approved entries; the [catalog](../../README.md) still lists all 200. Route count and tool count are navigation measures, not proof that an unseen challenge is solvable from the guide.

The guide added supplied-wireless-capture, EVTX, native-crash-triage, ZipCrypto, registry-hive, SQLite/WAL, SQL-condition, server-fetch, object-authorization, XOR/stream-reuse, declared-AES, Git-history, browser-profile-timeline, Android-preferences, iOS-plist, web-output-context, and web-cross-site-state routes. Each has a local [specialist workflow](../../SPECIALIST_WORKFLOWS.md) and primary source references. The last published snapshot passed its guide/export checks, 9 distribution tests, five browser sizes, and 12 benign recipe checks; `pngcheck` was unavailable for one recipe. The native route's checksec, ROPgadget, and cyclic commands ran on a benign local ELF. The SQLite check read a committed row from a copied database/WAL/SHM set. Existing symmetric helper tests include NIST GCM/CBC/CTR vectors and wrong-tag controls; the XOR/stream byte equations passed a synthetic arithmetic check with a shifted control, which does not prove any unknown plaintext. The Git route recovered a deleted synthetic blob through a rename and confirmed its exact source commit. The browser route's Chromium and Firefox SQLite queries recovered known synthetic URLs and UTC times, while unvisited-marker controls returned no rows. The plist snippet selected the same named value from synthetic XML and binary formats, and a malformed input failed. Hindsight, iLEAPP and ALEAPP are absent from this WSL environment, so their CLI paths remain source-reviewed only. The web output route separated encoded text, script execution and a CSP-blocked candidate on a synthetic loopback page, with an unchanged baseline. A six-case disposable HTTPS browser fixture compared same-site and cross-site form submissions: Lax omitted the session cookie on cross-site POST, None with Secure sent it, and a CSRF token blocked a state change even with that cookie. State was checked independently on the local server; no live challenge was used. The optional web toolkit adds selected WEB03 SQL, WEB05 traversal/template and WEB08 two-role checks. Synthetic loopback tests cover exact saved-query bytes, role cookie continuity, request limits and resume without replay; these are leads, not live exploitability or checker proof. Wireless conversion, EVTX parsing, registry parsing, bkcrack recovery, and live web-service behavior remain unverified on competition machines or challenge services.

The Android preferences route selected supported typed XML values, distinguished a conflicting backup, and rejected out-of-range integers, unsupported encodings/types, DTDs, malformed, oversized, symlinked and FIFO inputs. ALEAPP behavior on an actual extraction remains untested here.

The separate AndroidX Preferences DataStore reader selected boolean, int32, int64 and string keys from benign official-schema fixtures, including a mixed-type file with unrelated float, double, string-set and byte-array values. It rejected missing, duplicate, malformed, truncated, unsupported selected, oversized, symlinked and FIFO inputs; an export-and-clone smoke check read a known string and kept a missing key inconclusive. App-defined Proto DataStore, ALEAPP, a live Android extraction and competition-machine behavior remain untested.

The CBC padding-oracle route requires repeated, padding-specific response classes before attempting recovery. A benign one-block AES-CBC fixture returned 200 for the unchanged ciphertext, 400 after a last-IV-byte flip that forced invalid padding, 200 after a first-IV-byte control flip, and 422 for a malformed length, each repeated three times. In a separate loopback test, an isolated `padding-oracle-attacker` 0.2.4 recovered the exact independently known 16 padded bytes in 2,350 requests with `-c 1 --disable-cache`. A generic-response control gave false plaintext while exiting successfully after 17 requests. This demonstrates why error calibration and independent byte checks are required. The tool is not installed system-wide here; its competition-machine version, availability and real-endpoint behavior remain unverified.

The file path route used a disposable loopback file server with an allowed file, a missing-file control, and a known sibling file outside the serving root. A selected relative path returned the outside file's exact independently known bytes (SHA-256 `2c257fced6b8f361fe223fd859a850881b10561f7d44958b5515d9445f2920a0`). Separate 200 responses that echoed the path or returned a generic page contained none of those bytes. The existing four-request WEB05 helper classified the genuine read as a candidate, reflection as ambiguous because its missing-file controls differed, and the generic page as negative; untouched encoded query fields stayed byte-for-byte stable while WEB05 re-encoded the selected value. This tests local evidence discipline, not live-service behavior.

The optional model-gradient script now has an export-and-clone smoke check: where NumPy and PyTorch are installed, a two-step toy adapter must produce the bounded expected candidate; an isolated interpreter without those packages must return a clear dependency error. The packages are not in the core offline requirements, and a passing smoke check does not establish compatibility with an unseen challenge model or competition machine.
