A synthetic out-of-range XML time fell back to the header with a warning. Hayabusa and competition-machine behavior remain unverified.

The CBC padding-oracle route requires repeated, padding-specific response classes before attempting recovery. A benign one-block AES-CBC fixture returned 200 for the unchanged ciphertext, 400 after a last-IV-byte flip that forced invalid padding, 200 after a first-IV-byte control flip, and 422 for a malformed length, each repeated three times. In a separate loopback test, an isolated `padding-oracle-attacker` 0.2.4 recovered the exact independently known 16 padded bytes in 2,350 requests with `-c 1 --disable-cache`. The tool is not installed system-wide here; its competition-machine version, availability and real-endpoint behavior remain unverified.

The hash-length-extension route is conditional on a full SHA-1/256/512 secret-prefix MAC over exact bytes and an appendable message. An isolated copy of upstream `hlextend.py` (SHA-256 `61c3a54141c0f72e162ba6416cf4b2feabaa04b0f836a815af59e4ac2d67369a`) was checked against independent `hashlib` secret-prefix verifiers: for each of the three algorithms, only the true 14-byte secret length was accepted among 32 candidates; HMAC verifiers accepted none. All 96 forged message byte strings survived URL-component percent-encoding and decoding unchanged. This establishes the documented API and local control behavior, not that a real endpoint uses this construction or preserves padding bytes. The installed competition Kali module/version and live acceptance remain unverified.
